The root filesystem an app sees is a stack. Top to bottom:

```
the volume        writable; the only thing backed up
layers[n-1]
…                 the layers in desired.json, in the order listed
layers[0]
Debian            the guest image nibrunner ships; always the bottom
```

## Layers

A layer is an object in the artifact store, identified by its digest, with a `kind`:

| `kind` | Contents |
| --- | --- |
| `executable` | One program. The host packs it into an image at `destinationPath`. |
| `filesystem` | A squashfs or ext4 image. Attached as uploaded. |
| `downloaded-executable` | One program the host fetches itself from an `https` URL. Nothing goes in the store. |

```json
"layers": [
  { "kind": "filesystem", "digest": "<sha256, lowercase hex>", "objectKey": "base/runtime" },
  { "kind": "executable", "destinationPath": "/app/server", "digest": "<sha256, lowercase hex>", "objectKey": "my-server" }
]
```

A `downloaded-executable` names a `url` instead of an `objectKey`. Its `digest` is the program's:
of the response body, or, when the URL serves a zip and `zipEntry` names a file in it, of that file.
The host packs the program only once the bytes match, so a URL that changes is refused, not run.

```json
{
  "kind": "downloaded-executable",
  "destinationPath": "/opt/tool/tool",
  "url": "https://example.com/tool-linux-x64.zip",
  "zipEntry": "tool",
  "digest": "<sha256 of the tool file, lowercase hex>"
}
```

A download larger than 512 MiB is refused. The guest never needs network access for this: the host
does the fetching.

A layer is downloaded once per host and cached by digest. Ten apps on the same base image share
one copy. Reconciliation removes cached images once neither the desired document nor an instance
record references their digest. Sleeping instances keep their layers. A later deployment fetches
an evicted layer from the artifact store again; collection never deletes the stored object.

## The volume

The volume is the writable top of the stack. Every write goes there and persists. Nothing else
persists. An export contains the volume and the environment, never the contents of a layer. If a
layer and the volume both hold a file at the same path, the volume's copy wins.

## What runs

The guest's init runs `config.command` once the root is assembled: `program` with `args`, in
`workingDirectory`, with `environment`, as uid 65534.

```json
"command": {
  "program": "/app/server",
  "args": ["--port", "3000"],
  "workingDirectory": "/app",
  "environment": { "DATABASE_URL": "sqlite:///app/data.db" }
}
```

If no layer contains the working directory, the host creates it and gives it to uid 65534. The
program can write to the working directory and to `/tmp`. It is chrooted into the stacked root,
so it cannot reach the guest's init, the raw volume, or the host.

## From a Docker image

nibrunner does not run OCI images. To make a `filesystem` layer from one, export its filesystem
and pack it:

```bash
container=$(docker create --platform linux/amd64 my-image /bin/true)
mkdir rootfs
docker export "$container" | tar -x -C rootfs
docker rm "$container"
mksquashfs rootfs my-image.squashfs -comp zstd
sha256sum my-image.squashfs
```

Put `my-image.squashfs` in the artifact store and list it as a `filesystem` layer. The Debian
image nibrunner ships is built this way.

The export carries the filesystem only. The rest of the Dockerfile goes in `desired.json`:

| Dockerfile | `desired.json` |
| --- | --- |
| `ENTRYPOINT`, `CMD` | `config.command.program` and `args` |
| `WORKDIR` | `config.command.workingDirectory` |
| `ENV` | `config.command.environment` |
| `EXPOSE` | `config.httpPort`; other ports, [`config.ports`](/docs/guides/raw-ports) |
| `USER` | Nothing. The program runs as uid 65534. |
| `VOLUME` | Nothing. Every write goes to [the volume](#the-volume). |

The [reference](/docs/reference/desired) lists every field of a layer and a command.
