The host is configured by one file, `/etc/nibrunner/config.toml`. `nibrunnerd install` writes it
and every `nibrunnerd start` reads it. The [reference](/docs/reference/config) lists every key.

## Changing it

1. Edit `/etc/nibrunner/config.toml`.
2. Put any secret the new configuration needs in `/etc/nibrunner/host.env`.
3. Run `nibrunnerd start`.

`start` validates the whole file before doing anything, regenerates the files `install` wrote,
and restarts only the units whose configuration changed. If the file is invalid, the error names
the key and the reason.

## Validation rules

- **No key has a default.** If a section is present, every key in it must be set. A missing key
  is an error that names the key.
- **Unknown keys are errors.** A typo is reported as an unknown key, not as a missing one.
- **Only whole sections are optional.** `[proxy.http.tls]`, `[proxy.raw]`, `[metrics]` and
  `[logs]` and `[network.host_tcp]` can be omitted. If present, they must be complete.

Example errors:

```
volumes.backend is not specified, and nothing here is optional
volumes.zerofs is not read by the local-file backend, which is what volumes.backend says
proxy.http.port is not free, because 21000-28999 is what a slot takes for an app's loopback port
```

## What the installer writes

A complete configuration that works as-is:

| Key | Value |
| --- | --- |
| `max_apps` | What the machine can hold, [measured](/docs/guides/host-capacity) at install time. |
| `[paths]` | Everything under `/var/lib/nibrunner`. |
| `[artifacts]`, `[exports]` | Directories on the local disk. |
| `[volumes]` | `backend = "local-file"`: sparse files on the local disk. |
| `[proxy.http]` | Plain HTTP on all addresses, port 80. |
| `[logs]` | The newest 256 MiB of each app's output. |

Before running anything real on it, you will probably change two things:

- **The volume backend.** [`zerofs`](/docs/guides/volumes#zerofs) stores volumes in an object
  store. They survive the machine, and backups are taken from them.
- **The listener.** Add [`[proxy.http.tls]`](/docs/guides/https) to terminate TLS on the host.
  Behind an edge that terminates TLS, keep plain HTTP.

[`deploy/config.example.toml`](https://github.com/ilbertt/nibrunner/blob/main/deploy/config.example.toml)
shows every section filled in.

## Secrets

`config.toml` holds no secrets. Object-store credentials and the ZeroFS encryption password go in
`/etc/nibrunner/host.env`. `install` creates that file with every variable named and empty.
`nibrunnerd start` refuses to run while a variable the configuration needs is still empty.

## Ports

Each app slot reserves eight consecutive ports starting at 21000. Every listener in `config.toml`
must be outside the range `21000` to `21000 + 8 × max_apps − 1`. Port `0` is rejected.
`metrics.port` must differ from `proxy.http.port`.

## Calling a public endpoint on this host

Guests cannot initiate connections to their host by default. To let an app call an HTTPS
edge on the same host, name only its public address and port:

```toml
[network.host_tcp]
endpoints = ["203.0.113.10:443", "[2001:db8::10]:443"]
```

Replace these example addresses with the host's public addresses. This allows TCP only to
these exact endpoints. Other host ports and addresses, including management services, remain
blocked. Named egress denies still take precedence. Removing an endpoint also blocks existing
guest-initiated connections to it. Run `nibrunnerd start` to apply the change.

## Environment variables

- `NIBRUNNER_CONFIG`: path to a different configuration file.
- `NIBRUNNER_LOG`: a `tracing` filter for the daemon's log. Set it in the environment, not in
  the file.

Which apps run on the host is defined in `desired.json`, not in `config.toml`.

## Editor support

An editor with TOML schema support (Even Better TOML for VS Code, taplo) validates and
autocompletes the file when its first line is:

```toml
#:schema https://raw.githubusercontent.com/ilbertt/nibrunner/main/deploy/config.schema.json
```
